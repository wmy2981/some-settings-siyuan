# 使用者層級宣告補丁：`.patch.yml`

每個功能「要不要交出、屬於哪個頁籤、適用於哪一端、適配哪些思源版本」都由外掛原始碼裡的
功能宣告決定，隨外掛一起發佈；介面文案則來自隨外掛一起發佈的語言檔案。你若想在自己的機器上
改其中某一項（例如把某個功能徹底關掉、把它挪到別的頁籤、只讓它出現在行動端），或換掉幾句
介面文案，可以在外掛私有目錄裡維護一份 `.patch.yml`，外掛在載入功能**之前**依它覆蓋這些內容。

這份檔案**只能由你手動建立與修改**：外掛不產生範本、不提供面板入口、也不監聽變化。
設定面板裡不會因為它多出任何項目、按鈕或說明。

## 檔案位置

```
<工作空間>/data/storage/petal/some-settings-siyuan/.patch.yml
```

檔名固定、以點開頭，和每個功能自己的 `feature-<功能 id>` 設定檔案放在同一個目錄裡。
檔案不存在就是「沒有補丁」，屬於最常見的正常狀態，外掛不會建立它，也不會提示任何東西。

## 欄位

功能宣告放在頂層鍵 `features` 下，依**功能 id** 分組，每個功能可以寫下面五個欄位之一或全部。
欄位省略表示沿用原始碼宣告，**不等於**解除限制。

| 欄位            | 覆蓋的宣告               | 合法值                                                                                        |
| --------------- | ------------------------ | --------------------------------------------------------------------------------------------- |
| `enabled`       | 功能是否隨外掛交出       | `true` / `false`                                                                              |
| `category`      | 功能所在的設定頁籤       | `ai` / `editor` / `doc-tree` / `appearance` / `connection` / `settings` / `bazaar` / `plugin` |
| `frontends`     | 適用前端                 | `desktop` / `mobile` 組成的清單；`[]` 表示兩端都不適用；`null` 或空值表示不限前端             |
| `minAppVersion` | 支援的最低思源版本（含） | 思源版本號字串，如 `"3.8.7"`；`null` 或空值表示解除下限                                       |
| `maxAppVersion` | 支援的最高思源版本（含） | 思源版本號字串，如 `"3.9.0"`；`null` 或空值表示解除上限                                       |

`category` 填的是頁籤 id，不是頁籤名稱。版本號建議加引號：`3.8` 這種寫法不合法，
`"3.8.7"` 才是完整版本號。

## 範例

```yaml
features:
  # 把「智慧體輸入框按 Enter 送出」關掉：不載入它的設定、不掛載、預設不進設定面板
  agent-enter-to-send:
    enabled: false

  # 挪到「編輯器」頁籤，並同時限定兩端
  desktop-command-panel-slim:
    category: editor
    frontends: [desktop, mobile]

  # 只在自己的思源版本上試用
  tab-title-markdown:
    minAppVersion: "3.8.7"
    maxAppVersion: "3.9.0"

  # 解除原始碼裡的兩處限制；適用端也一併解除
  mobile-console-log:
    frontends: null
    maxAppVersion: null
```

一個功能可以同時寫幾個欄位，效果疊加。`frontends` 也可以寫成區塊清單：

```yaml
features:
  mobile-dock-blur:
    frontends:
      - mobile
```

## 解除限制的寫法

原始碼裡已經宣告了 `maxAppVersion`（上游實作之後這份補丁就該退場）時，**不寫這個欄位等於沒改**，
功能仍然依原始碼宣告的上限隱藏。要讓它在更高的思源版本上也出現，必須明確寫空值：

```yaml
features:
  tab-title-markdown:
    maxAppVersion: null # 寫成 maxAppVersion: 也是同一個意思
```

`minAppVersion` 與 `frontends` 同理。反過來說，`frontends: []` 是「兩端都不適用」，
不是「兩端都適用」—— 想把功能在自己機器上停用又不想改 `enabled`，寫空清單即可。

## 覆蓋介面文案（i18n）

除了功能宣告，補丁還能依介面語言覆蓋外掛自帶的文案。頂層鍵是 `i18n`，第二層是介面語言代碼，
第三層才是 i18n 鍵與文案：

```yaml
i18n:
  zh-TW:
    feature.clearConfig.action: "清除全部設定"
    panel.unavailable.frontend: "僅 {platform} 可用"
```

* **只作用於目前的介面語言。** 外掛執行時只載入一份語言檔案（介面語言那份），寫其他語言的翻譯
  不會生效，也不會校驗其中的鍵值；但 `i18n` 的整體結構（語言 → 鍵值表）仍必須合法。語言代碼
  寫成 `zh-CN` 或歷史寫法 `zh_CN` 都可以。
* **只能改現有的鍵。** 鍵必須已經出現在外掛自帶的語言檔案裡；不存在的鍵會被跳過（見下一小節）。
  值原樣使用：文案裡的 `{platform}`、`{version}`、`{count}` 這類佔位符仍由用到它的程式碼替換，
  與把這句話直接寫進 `i18n/<語言>.json` 的效果完全一致。

### 不存在的功能 id 與 i18n 鍵

補丁裡點名的功能 id 或 i18n 鍵如果在這台機器上不存在（id 寫錯、外掛升級後刪掉了這個功能或這條
文案），那一條會被**靜默跳過**，其餘條目照常生效。這樣一份舊補丁不會因為外掛升級刪掉一條文案就
整份失效；代價是打錯 id 時沒有任何報錯，只能靠詳細日誌裡那行 `skipped unknown …` 發現。

## 生效時機

* 只在**外掛載入時**讀一次。改完檔案後到「設定 → 市集 → 已下載 → Some Settings」裡關閉再啟用外掛，
  或者重新載入外掛；外掛不會監聽檔案變化。
* 文案覆蓋在載入功能之前寫進宿主已經載入的那份語言檔案，所以面板、提示條、動作按鈕與各功能
  顯示的都是補丁後的文字，面板搜尋也依它比對。
* 補丁改的是**功能交付宣告**，不是各功能面板裡那個執行開關。被 `enabled: false` 關掉的功能
  連設定都不載入；被補丁重新開啟的功能，仍然要它自己的開關打開才會真正執行。
* 關掉一個功能等於開發者沒交出它：不載入設定、不掛載、預設不進設定面板。
  打開「此外掛」頁籤裡的「顯示不可用的設定」後，它會在自己那個頁籤底部灰顯出來，
  原因寫的是「已被使用者停用」。
* 補丁能改分類：正常項目和灰顯項目都進新分類，頁籤內的順序仍與外掛裡的註冊順序一致。
* 補丁能改適用端與版本區間，灰顯原因依補丁後的宣告重算，不會殘留原始碼宣告對應的原因。

## 出錯時會怎樣

**任何一處不合法都讓整份補丁不生效**，所有功能回到外掛自帶的宣告，不會出現「一半生效」的狀態。
（唯一的例外是點名了不存在的功能 id 或 i18n 鍵：那一條只被跳過，見上一節。）
會讓整份補丁作廢的情況包括：

* YAML 語法錯誤（錯誤訊息帶行號）；
* 頂層出現 `features` 與 `i18n` 以外的鍵，或 `features` 不是「功能 id → 欄位」這種結構；
* 未知欄位、欄位型別不對；
* `i18n` 不是「語言 → 鍵 → 文案」的結構，或者目前介面語言裡已有的某個鍵值不是字串（空字串
  同樣不行）；不存在的鍵連同它的值一起跳過；
* 不合法的 `category`、不合法的適用端、重複的適用端；
* 不合法的版本號，或者與原始碼宣告合併後得到 `minAppVersion` 高於 `maxAppVersion` 的空區間。

出錯時：

* 外掛照常啟動，設定面板、設定入口與其他功能全部正常 —— 補丁永遠不阻斷使用；
* 打開詳細日誌後主控台會有一條 `WARN`，寫明失敗原因（不回顯檔案內容）；
* 每次成功打開此外掛的設定面板後，會彈一條非阻斷的提示條，告訴你補丁無效。
  補丁在面板裡沒有項目，不看這條提示就只能靠主控台才發現自己改錯了；
* 沒有檔案、空檔案、只有註解、`features: {}`、`i18n: {}` 都是「沒有覆蓋」，不提示任何錯誤。

## 維護操作邊界

* 「匯出設定」「匯入設定」「清除此外掛設定」只處理目錄裡的 `feature-*` 設定檔案，
  **不包含** `.patch.yml`，這些動作不會改動它。
* 解除安裝外掛不會刪除外掛私有目錄裡的任何檔案：`.patch.yml` 與各功能的設定都留在原處，
  重裝外掛後照舊生效。
* 面板與面板搜尋裡不會出現補丁自身的項目、控制項、路徑、內容或狀態。補丁的 `i18n` 段只能覆蓋
  現有的文案，不會憑空新增一條沒人使用的鍵。

## 支援的 YAML 寫法

只認這份檔案真正用得上的寫法，其餘一律報錯（而不是猜）：

* 區塊映射，縮排只用空格，每層建議兩個空格；
* 值：空值（`key:`、`null`、`~`）、`true` / `false`、純文字、單引號與雙引號字串、
  行內清單 `[a, b]`、空映射 `{}`、區塊清單（每行一項 `- a`）；
* 註解：整行 `# …`，以及值後面隔了空白的 `# …`（引號裡的 `#` 不算註解）。

不支援：錨點與別名（`&` / `*`）、多文件（`---`）、區塊純量（`|` / `>`）、`{}` 之外的行內映射、
標籤（`!!`）、Tab 縮排，以及 `yes` / `no` / `on` / `off` 這類有歧義的布林寫法 —— 布林值請寫
`true` / `false`。

> 補丁是進階入口：強行啟用一個還沒交付的功能、或改動適用端與版本限制之後，外掛不承諾它一定能正常運作。
