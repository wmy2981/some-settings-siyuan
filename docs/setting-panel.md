* **面板走思源原生的 `Setting`**：对话框（标题、正文区、动作区、关闭方式）全部由宿主创建，
  插件只在 `setting.open()` 返回后往正文里填自己的面板。这样移动端不需要插件做任何事 ——
  新版宿主在 `Setting.open()` 内部用 `MobileDialog` 渲染，插件设置就自动变成底部抽屉：
  抓手、拖动、遮罩、返回键、可视视口与键盘避让都由宿主接管，插件不复制任何一套。
  桌面端仍是居中弹窗；设置窗口模式下 `Setting.close()` 还会替插件收掉那个窗口。
  仓库固定的 `siyuan@1.2.8` 类型里还没有 `setting.dialog` / `setting.close()`（较新的 petal
  已经声明），所以只在 `setting-dialog.ts` 里做一处窄类型扩展（`SettingWithDialog`），不要扩散成
  全局断言；升级 SDK 后把这处扩展删掉。
* **页签结构，每页只有一层**：分类按功能**作用到的思源原生功能**划分（人工智能 / 编辑器 /
  文档树与页签 / 界面与外观 / 连接与内核 / 设置与集市 / 插件自身），一个分类一个页签，
  没有内容的不出现；页签内容直接是设置行，**任何形式的嵌套分组都不允许**。
  不再使用「功能 / 界面 / 关于」这种从插件视角出发的划分 —— 它会把同一块原生界面的设置
  拆到不同页签里，用户找一个设置只能通读三个页签。
  `SettingField` 因此也没有 `group` 型 —— 从类型上就写不出层级。
* 页签的两套外观都照抄内核，且只借**样式类**，不借内核会认的结构类：
  * 桌面端：弹窗左侧一列（`.some-settings-panel__side` + `b3-list-item`），形制照抄内核设置的
    `.config__panel > .config__side`；窗口窄到 750px 以下时侧栏收成一列图标（内核同款做法）
  * 移动端：顶部一条（`.layout-tab-bar` + `item`），照抄内核代码片段弹窗；**吸顶**，
    所以底色必须取 `--b3-theme-surface`（与弹窗容器、移动端底部抽屉的底色完全一致），
    不能取内核给页签栏的 `--b3-theme-background`，也不能留透明 —— 深浅主题下两者都不一样，
    页签栏会变成标题下面一条色带，透明则会让行从它下面透出来。
    **不加圆角**：面板的页签栏上面还有标题栏，不在容器圆角上，那圈圆角只会把容器底色从两个角露出来
  * 移动端页签栏**可以左右滑动**：分类有七个，一屏放不下。每一项 `flex: 0 0 auto`
    并给一个能整块点中的最小宽度，靠 `overflow-x: auto` 横向滚动，不做等分也不换行。
    **不要再用 `item--full`**：它让每一项都抢宽度，页签一多就全挤成等分，滑都滑不动。
    **也不要加 `scroll-snap`**：吸附会在每一项上顿一下、把手指的惯性打断，滑起来一格一格地发黏；
    页签栏本来就是短条，惯性滑到看得见的位置比被吸附到整项更顺手
  * 页签图标两端都显示（同一个 symbol），一项一个，跟着分类走而不是跟着功能走
  * **切页之后把选中的页签滚进可见范围**（`setting-dialog.ts` 的 `revealTab()`）：移动端页签栏
    每次打开都停在最左边，恢复了第 4、5 个页签时选中的那一项还在屏幕外 —— 类名换到了它身上，
    用户看到的却还是开头几个，「记住了页签」看起来等于没记住。位移取最小值（已经完整可见就不动，
    只露出一半就贴到最近的边），只改页签栏自己的 `scrollLeft` / `scrollTop`；桌面端左侧列表同样处理。
    **不要用 `scrollIntoView()`**：它会连带滚动所有祖先（弹窗内容区、宿主抽屉、整个页面），
    为了恢复一个页签把整页带偏。抽屉刚挂上、页签栏宽度还是 0 时量不出要不要滚，
    由 `revealTab()` 在下一帧补一次（`cancelRevealFrame()` 在关面板与重开时收掉这一帧）
  * ⚠️ **不要用 `.config__tab-container`**：内核打开自己的设置弹窗时会
    `dialogs.find(item => item.element.querySelector(".config__tab-container"))?.destroy()`，
    借了这个类，用户再开一次思源设置就可能连带把本插件的面板销毁掉。
    同理 `.config__side` / `.config__tab-wrap` 也都不用，只在自己的类名里复刻它们的形制。
* 滚动分两种：
  * 桌面端每一页自己滚（`.some-settings-panel__view` 绝对定位铺满），弹窗内容区因此不留内边距、
    也不滚动（由 `setting-dialog.ts` 的 `applyDesktopLayout()` 写成行内样式）：否则页签栏会被一起滚走
  * 移动端**按内容自然高度排版**（`--mobile` 去掉绝对定位、`height: auto`），整块交给宿主的内容区
    滚动、页签栏吸顶。抽屉高度是宿主量内容的自然高度再按视口裁限的，写死高度（`height: 100%`
    在自动高度的父级里退化成 `auto`）会让抽屉塌成一条或者一打开就空出一截
* 入场前给弹窗容器挂 `.some-settings-layer`（`core/layer.ts` 的 `preheatDialogLayer()`）：该模块注入的
  样式让容器、`.b3-dialog__content` 与当前可见的 `.some-settings-panel__view` 常驻
  `will-change: transform`（只算桌面端那一页；移动端整块由内容区滚动，不再给页签内容建层）。
  `Dialog` 的入场是 `transform` / `opacity` 过渡，
  过渡期间临时建层、结束时再拆层，WebView 在拆层那一帧会闪一帧旧画面；预热之后入场期间
  不再建层/拆层。**只补图层提示**：不覆盖宿主的 `transition`、不改 `b3-dialog--open` 的时序、
  不在 `transitionend` 后移除。`Setting` 用的是同一个 `Dialog`，所以在 `setting.open()`
  返回后同步补类（SDK 的 `DialogOptions` 里还没有 `containerClassName`），补类发生在宿主
  50ms 后才加的 `b3-dialog--open` 之前。
  **设置面板与所有自建 `Dialog` 都走同一个入口**，不要各写一份。
  **图层带来的闪烁与下面「聚焦」带来的闪烁是两个独立问题**，只挡一个不够，也不能用其中一个的消失
  代替另一个。
* 打开路径**不聚焦任何输入控件**：宿主 `Setting.open()` 会把焦点交给正文里的第一个
  `input` / `textarea`，移动端那一下会顶起软键盘、压缩可视视口。面板用
  `core/frontend.ts` 的 `withoutMobileInputFocus()` 只包住**同步**的 `open()` 调用：
  期间临时接管 `HTMLElement.prototype.focus` 挡掉 `input` / `textarea`，`finally` 立刻还原，
  容器等非输入控件的聚焦照常放行；桌面端直接执行、不碰宿主行为。用户随后点输入框仍能正常编辑。
* **面板内置全局搜索**（issue #119）：搜索只是面板自己的**过滤机制** —— 不新增 feature、不加启用开关、
  不读写任何配置。匹配与高亮的纯逻辑在 `core/search.ts`，DOM 侧的显隐与高亮写入在 `setting-dialog.ts`，
  两者靠行上的私有元数据（`data-ss-tab-panel` / `data-ss-feature` / `data-ss-row`）对齐。
  * **输入时不重建面板**：只切 `fn__none` 与局部文本，所以输入框焦点、滚动位置、静默期里待写的文本都不受影响；
    过滤后要重算 `config-item--last-visible`，否则下分割线会落在已经藏起来的行上。
  * **有查询后收起分类导航**（桌面端左侧栏、移动端页签栏），两端都是过渡而不是 `fn__none`：`display:none`
    没有过渡，一开一收是硬跳。移动端页签栏的高度是内容撑出来的 `auto`，`auto → 0` 过渡不了，所以收起前
    把实测高度写进变量当起点并**强制一次回流**（否则变量和类落在同一次样式计算里，浏览器只看到 `auto → 0`），
    展开结束后再把高度交还给内容。系统里开了「减少动效」时整体关掉过渡。
  * **清空（一键清空、手动删词、`Esc`）后原样恢复**：分类导航、当前页签、最后一行标记与搜索前的滚动位置。
    查询只存在于本次面板会话，不持久化；动态文案更新了索引也不立刻改变当前结果，只有查询文本真的变了才重算。
  * **高亮只新建文本节点与 `<mark>`（`textContent` 赋值），不拼 HTML 字符串** —— 关键词来自用户输入，
    走字符串替换就是一次注入。只高亮界面上真的看得见的命中文字。
  * **索引范围就是面板上看得见的东西**：分类名、功能的 `id` / 名称 / 说明、设置项的 `key` / 标题 / 说明、
    placeholder、下拉选项标签、说明块的文字、按钮文字；不收用户填的值与开关状态，也不读配置存储。
    静态 i18n 文案同时索引中英文：宿主只交当前语言那一份，所以 `setting-dialog.ts` 静态引入两份语言文件
    （打包体积增加约 56 KB，换来「英文界面下也能用中文搜」）。
  * **匹配规则**：拆词后 AND，且必须落在同一个字段上（功能名命中「图片」、设置项命中「压缩」不算命中）；
    英文忽略大小写、连续子串；同一静态字段的中英文算一个匹配域，跨语言拼不出假命中。
    不做拼音、首字母、繁简、全半角、同义词、模糊或正则。
  * **快捷键挂在 `document` 的捕获阶段**：宿主的「在文档里搜索」也听着 `Ctrl/Cmd + F`，只有捕获阶段能赶在
    它前面。`/` 聚焦搜索框，焦点已经在文本 / 数字 / 下拉等编辑控件里时不劫持；`Ctrl/Cmd + F` 无条件拦下
    宿主搜索并聚焦搜索框；`Esc` 只在有查询时清空、不关面板。组合输入（中文输入法）期间不过滤，也不处理快捷键。
  * 输入框里那颗一键清空按钮刻意用 `type="text"` 而不是 `type="search"`：浏览器的原生清除按钮不受主题控制，
    形状也和内核那套图标对不上。
* 每个功能的名称与说明渲染成一行（`.some-settings-panel__sub`），它就是一行
  `b3-label config-item`，位置在该功能的参数行之前（一页里可以有多个功能）。
  **功能自己那个默认关闭的开关就放在这一行**，不再单独占一行；功能还有参数时，
  参数行排在它下面。
  拿 selector 当开关的功能（声明了 `isEnabled`）同理：那个 select 也放这一行，
  **不再另起一行显示**——它就是开关，不是参数。
  带开关的功能行**整行可点**：这一行用 `<label>` 包住开关，点功能名或它的说明就等于点开关
  （`render()` 里的 `inline` 控件，与 `switchRowHtml` 同一个做法）。**拿下拉当开关的功能行不能这么写**，
  否则点一下功能名会顺手把下拉拉开。
* **面板里的文案一律常规字重**：功能名（父项）、它下面的子设置项、动作行都不加粗，
  说明再用 `.b3-label__text` 更小更淡。层级只由**子行缩进 + 左侧层级引导线**表达，
  所以 `PANEL_CSS` 里没有任何一处抬升字重。不要再给某一类行单独加粗或改字号：
  「全部 `.config-item__main` 加粗」与「只有功能名加粗」两版都试过，前者层级消失，
  后者把视觉重心全拉到标题上、参数行被压成一片灰。
* **子设置行统一缩进一小格**：功能名那一行（`__sub`）不动，它下面的参数行、说明块、动作行
  都带 `.some-settings-panel__child`，由 `PANEL_CSS` 加 `padding-inline-start`（桌面端 40px、
  ≤750px 时 26px，跟着行自己的内边距走）。缩进加在整行上，移动端控件折到第二行时一起对齐；
  分割线仍由内核画满整行。类名由行构造器自己带上（`subtitleRowHtml` 之外的那六个只产出子行），
  功能声明里不用写任何东西，**新功能、新行类型都不用单独适配**。
* **子设置行左侧有一条层级引导线**：一条竖线把同一功能的所有子行串起来，每一行在自己的
  垂直中线处伸出一小段横折指向文案（树形 ├ / └）。线**画在子行自己的伪元素上**
  （`::before` 是竖线、`::after` 是横折，颜色取 `--b3-border-color`），所以它天然从功能名
  那一行的下沿开始，**不需要、也不允许为它加分组容器**——页签里的行必须保持平铺。
  最后一个子行由 `setting-dialog.ts` 拼行时经 `markLastChildRow()` 打上
  `some-settings-panel__child--last`，竖线只画到折角处收成 └（否则会一直画到行底，
  看着像下面还有内容没显示完）；这个标记**不能交给 `:last-child`**，行是跨功能平铺的，
  它只看得见整页最后一行，跟 `config-item--last-visible` 是同一个道理。
  窄屏（≤750px）缩进收到 26px 时，竖线与横折的横向位置由媒体查询一起收（12px / 8px，
  与文案之间留 6px），**改了缩进不改这里，线会压到文字上**。
* **面板没有底栏**：不出现任何「保存 / 取消」按钮，宿主建的那条 `.b3-dialog__action` 由
  `hideActionBar()` 整块加 `fn__none` 收起，插件也不往里放按钮。
  **`Dialog` 自己不生成动作区**（只有 `Setting` 会），所以导出 / 导入这类自建窗口要按钮就得自己拼
  `.b3-dialog__action`。
* **改完即落盘**，没有草稿、也没有事务语义：
  * 控件一变就写进该功能自己的配置文件，界面显示的值永远等于磁盘上的值；
  * 开关与下拉改一次写一次；文本 / 数字框打字过程按 400ms 静默期合并写盘（连打几个字只写一次文件），
    失焦（change）立即写，关面板时把还在静默期里的那一次补上；
  * 与磁盘相同的值不重复写盘：下拉重选同一项、开关重设同一状态都算没改；
  * 写盘失败或读回校验失败时，`ConfigStore.patch()` 先把内存态退回改动之前，面板再把控件
    改成磁盘上的值并弹出错误 —— 不允许静默失败，也不允许界面停在「看着改了、其实没存」。
* 优先使用思源原生类名，保证与内置设置面板一致；具体用了哪些类看 `core/ui.ts` 的行构造器。
* 设置字段支持 `switch` / `text` / `textarea` / `number` / `select` 五种取值控件，外加两种不取值的行：
  `button` 动作行与 `note` 说明块：
  * `textarea` 与 `text` 存同一种值（字符串），只是控件换成多行输入框，供「一行一项」这类列表型输入
    （例如作者名单）使用；`rows` 控制可见行数（默认 6）。它塞不进「右侧定宽 200px」那一格，
    所以这一行折成上下两段：标题与说明占满一行、输入框整行落在下面，层级引导线的横折对齐标题那一行。
    打字过程同样按静默期合并写盘，失焦立即写
  * `select` 的 `options` 可以换成 `optionsProvider: () => SettingOption[]`，
    在面板每次打开时现算候选集（笔记本、插件列表这类只有运行时才知道的数据）；
    走这条路时 `core/config.ts` 不做白名单校验，失效的值由功能自己兜底
  * `button`（`label` + `onClick`）**只用于「点击即打开某个窗口」这类没有可持久化取值的入口**，
    不参与配置读写，只读 / 发布模式下禁用。
    **它同样绕过面板那套「改完即落盘」，所以副作用必须自己落盘、并且立刻把面板上的控件改成新值**：
    否则用户配完却忘了开开关，功能永远不会挂载（看起来就是「配了没用」）；或者磁盘已经变了、面板还显示
    旧值（`updateConfig` 就是干这件事的）。
    `label` 通常是 i18n key；也可以写成 `(context) => string`，此时每次打开面板求值、
    **返回值直接当文案**（函数内部自己用 `context.i18n()` 取词），用于按钮文字要跟着
    运行期状态变的入口 —— 例如「目标插件装了没装」决定按钮是「打开设置」还是「去集市安装」。
    它不是用来放普通操作按钮的 —— 面板底栏本来就不存在。
    `appearance: "block"` 换成思源「关于」页那颗捐赠按钮的形制：外壳 `fn__size200` +
    `fn__block` 撑满这一格（桌面端 200px，窄屏由媒体查询放开到整行），底色由 `tone` 决定
    —— `primary` 取主题色，`pink` 是思源捐赠按钮那颗粉（`b3-button--pink`）。图标两种写法：
    `icon` 填思源内置 symbol 名（如 `iconGithub`），`iconSvg` 原样插入一段现成的 SVG 标记 ——
    思源「关于」页那颗捐赠按钮前面那张渐变爱心就没有对应 symbol，只能走后者。只给「去点星」「捐赠」这类要突出的入口用，
    其余动作行仍是默认的 `b3-button--outline`，靠右定宽、不带图标。
    点击由面板统一经 `bindPendingClick` 绑定：执行期间按钮禁用，重复点击不会把同一段流程
    跑两遍（「导出配置」这类先异步准备再开窗的入口，连点会一次冒出多个弹窗），
    功能自己不用写防重。
  * `onClick` 会收到一个 `FeatureActionContext`：动作行**不参与挂载**，因此没有 `FeatureHost`，
    需要 i18n、全部功能 id，或「清空本插件配置」这类全局能力时只能从这里取
  * `note`（`text` + 可选的 `values` / `labels` / `actions`）是**只读说明块**：
    没有取值，不参与配置读写，也不落盘（`core/config.ts` 直接跳过它）。
    只用于面向用户的说明（插件性质、版本号、仓库地址这类），不是设置项。
    `text` 是 i18n key，值按 `\n` 分段，其中的 `{name}` 占位符按 `values` 替换，
    替换值本身是 http(s) 链接时渲染成可点的链接：链接文字默认是地址本身，
    `labels` 里给了同名短写时用短写（仓库地址因此显示成 `owner/repo`）。
    点击时先按内核 `openLink` 的顺序 `emit("open-link", …)` 问一遍插件 ——
    本插件的「外链跳转前确认」正是这样拦下它的 —— 没人拦下才走思源重写过的 `window.open`。
    因此**版本号、仓库地址这类事实不要在文案里手写**：由功能从插件清单里读出来当 `values` 传进来。
    可选的 `actions`（与 `button` 同一套 `label` / `appearance` / `tone` / `icon` / `iconSvg` / `onClick`）
    是这段说明配套的入口，比如「关于」里那颗点星与捐赠：桌面端整行变成「左文字 + 右按钮」，
    按钮竖着叠在右侧、每颗 200px，与「导出配置」那些行同一个位置和宽度；
    窄屏才改回文字在上、按钮整行在下。点击同样经 `bindPendingClick`，只读 / 发布模式下禁用
* **每个功能的第一个设置行必须是默认关闭的开关**（或声明 `isEnabled`），见 [AGENTS.md](../AGENTS.md) 第 3 节。
* **行与行之间的间距与分割线全部交给内核**（子行缩进与窄屏内边距例外，由 `PANEL_CSS` 给）。
* 面板每次打开都会**重写**自己那份 `<style>` 的内容（见 [development.md](./development.md) 的「样式」一节），
  所以改 `PANEL_CSS` 后重载插件就能生效，不必整页刷新。
* 一页的行是跨功能拼出来的，`:last-child` 看不见真正意义上的最后一行，
  所以由 `setting-dialog.ts` 的 `markLastRow()` 给最后一行加 `config-item--last-visible`，
  去掉它多余的下分割线。
* 窄屏（≤750px，与内核同一断点）由 `PANEL_CSS` 的媒体查询处理：页签内容与行内边距收窄，
  桌面端的侧栏收成一列图标；折行本身由内核的 `.config-item` 规则完成，插件不再自己折。
  作用域靠 `.b3-dialog__body .some-settings-panel` 这个前缀，不依赖容器上另挂的类
  （容器类没挂上过一次，媒体查询就整段落空）。
* **单位标签必须 `white-space: nowrap`**，否则窄屏下会被压成一列一个字。
  数字行的 `unit` 与其它文案一样按 **i18n key** 解析：`"px"` / `"ms"` / `"%"` / `"vh"`
  查不到就原样返回，而 `"kernelAutoReconnect.times"` 这种才会翻成「次」/ "times"。
  `setting-dialog.ts` 里**不能**把 `unit` 当字面量直接拼进 HTML——踩过一次，面板上真的
  显示了那串 key。
