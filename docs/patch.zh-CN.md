# 用户级声明补丁：`.patch.yml`

每个功能「交不交出、属于哪个页签、适用于哪一端、适配哪些思源版本」都由插件源码里的
功能声明决定，随插件一起发布；界面文案则来自随插件发布的语言文件。你如果想在自己的机器上
改其中某一项（例如把某个功能彻底关掉、把它挪到别的页签、只让它出现在移动端），或者换掉
几句界面文案，可以在插件私有目录里维护一份 `.patch.yml`，插件在装载功能**之前**按它覆盖
这些内容。

这份文件**只能由你手动创建和修改**：插件不生成模板、不提供面板入口、也不监听变化。
设置面板里不会因为它多出任何条目、按钮或说明。

## 文件位置

```
<工作空间>/data/storage/petal/some-settings-siyuan/.patch.yml
```

文件名固定、以点开头，和每个功能自己的 `feature-<功能 id>` 配置文件放在同一个目录里。
文件不存在就是「没有补丁」，属于最常见的正常状态，插件不会创建它，也不会提示任何东西。

## 字段

功能声明放在顶层键 `features` 下，按**功能 id** 分组，每个功能可以写下面五个字段之一或全部。
字段省略表示沿用源码声明，**不等于**解除限制。

| 字段            | 覆盖的声明               | 合法值                                                                                        |
| --------------- | ------------------------ | --------------------------------------------------------------------------------------------- |
| `enabled`       | 功能是否随插件交出       | `true` / `false`                                                                              |
| `category`      | 功能所在的设置页签       | `ai` / `editor` / `doc-tree` / `appearance` / `connection` / `settings` / `bazaar` / `plugin` |
| `frontends`     | 适用前端                 | `desktop` / `mobile` 组成的列表；`[]` 表示两端都不适用；`null` 或空值表示不限前端             |
| `minAppVersion` | 支持的最低思源版本（含） | 思源版本号字符串，如 `"3.8.7"`；`null` 或空值表示解除下限                                     |
| `maxAppVersion` | 支持的最高思源版本（含） | 思源版本号字符串，如 `"3.9.0"`；`null` 或空值表示解除上限                                     |

`category` 填的是页签 id，不是页签名。版本号建议加引号：`3.8` 这种写法不合法，
`"3.8.7"` 才是完整版本号。

## 示例

```yaml
features:
  # 把「智能体输入框回车发送」关掉：不装载它的配置、不挂载、默认不进设置面板
  agent-enter-to-send:
    enabled: false

  # 挪到「编辑器」页签，并同时限定两端
  desktop-command-panel-slim:
    category: editor
    frontends: [desktop, mobile]

  # 只在自己的思源版本上试用
  tab-title-markdown:
    minAppVersion: "3.8.7"
    maxAppVersion: "3.9.0"

  # 解除源码里的两处限制；适用端也一并解除
  mobile-console-log:
    frontends: null
    maxAppVersion: null
```

一个功能可以同时写几个字段，效果叠加。`frontends` 也可以写成块状列表：

```yaml
features:
  mobile-dock-blur:
    frontends:
      - mobile
```

## 解除限制的写法

源码里已经声明了 `maxAppVersion`（上游实现之后这份补丁就该退场）时，**不写这个字段等于没改**，
功能仍然按源码声明的上限隐藏。要让它在更高的思源版本上也出现，必须显式写空值：

```yaml
features:
  tab-title-markdown:
    maxAppVersion: null # 写成 maxAppVersion: 也是同一个意思
```

`minAppVersion` 与 `frontends` 同理。反过来，`frontends: []` 是「两端都不适用」，
不是「两端都适用」—— 想把功能在自己机器上停用又不想改 `enabled`，写空列表即可。

## 覆盖界面文案（i18n）

除了功能声明，补丁还能按界面语言覆盖插件自带的文案。顶层键是 `i18n`，第二层是界面语言代码，
第三层才是 i18n 键与文案，结构就是：

```yaml
i18n:
  zh-CN:
    feature.clearConfig.action: "清除全部配置"
    panel.unavailable.frontend: "仅 {platform} 可用"
```

* **只作用于当前界面语言。** 插件运行时只加载一份语言文件（界面语言那份），写其他语言的翻译
  不会生效，也不会报错；语言代码写成 `zh-CN` 或历史写法 `zh_CN` 都可以。
* **只能改现有的键。** 键必须已经出现在插件自带的语言文件里；不存在的键会被跳过（见下一小节）。
  值原样使用：文案里的 `{platform}`、`{version}`、`{count}` 这类占位符仍由用它的代码替换，
  与把这句话直接写进 `i18n/<语言>.json` 的效果完全一致。

### 不存在的功能 id 与 i18n 键

补丁里点名的功能 id 或 i18n 键如果在这台机器上不存在（id 写错、插件升级后删掉了这个功能或这条
文案），那一条会被**静默跳过**，其余条目照常生效。这样一份旧补丁不会因为插件升级删掉一条文案就
整份失效；代价是打错 id 时没有任何报错，只能靠详细日志里那行 `skipped unknown …` 发现。

## 生效时机

* 只在**插件加载时**读一次。改完文件后到「设置 → 集市 → 已下载 → Some Settings」里关闭再启用插件，
  或者重载插件；插件不会监听文件变化。
* 文案覆盖在装载功能之前写进宿主已经加载的那份语言文件，所以面板、提示条、动作按钮与各功能
  显示的都是补丁后的文字，面板搜索也按它匹配。
* 补丁改的是**功能交付声明**，不是各功能面板里那个运行开关。被 `enabled: false` 关掉的功能
  连配置都不装载；被补丁重新打开的功能，仍然要它自己的开关打开才会真正运行。
* 关掉一个功能等于开发者没交出它：不装载配置、不挂载、默认不进设置面板。
  打开「插件自身」页签里的「显示不可用的设置」后，它会在自己那个页签底部灰显出来，
  原因写的是「已被用户禁用」。
* 补丁能改分类：正常条目和灰显条目都进新分类，页签内的顺序仍与插件里的注册顺序一致。
* 补丁能改适用端与版本区间，灰显原因按补丁后的声明重算，不会残留源码声明对应的原因。

## 出错时会怎样

**任何一处不合法都让整份补丁不生效**，所有功能回到插件自带的声明，不会出现「一半生效」的状态。
（唯一的例外是点名了不存在的功能 id 或 i18n 键：那一条只被跳过，见上一节。）
会让整份补丁作废的情况包括：

* YAML 语法错误（报错带行号）；
* 顶层出现 `features` 以外的键，或 `features` 不是「功能 id → 字段」这种结构；
* 未知字段、字段类型不对；
* `i18n` 不是「语言 → 键 → 文案」的结构，某一项的值不是字符串，或者键在插件自带的语言文件里
  不存在；
* 非法的 `category`、非法的适用端、重复的适用端；
* 非法的版本号，或者与源码声明合并后得到 `minAppVersion` 高于 `maxAppVersion` 的空区间。

出错时：

* 插件照常启动，设置面板、设置入口与其他功能全部正常 —— 补丁永远不阻断使用；
* 打开详细日志后控制台会有一条 `WARN`，写明失败原因（不回显文件内容）；
* 每次成功打开本插件的设置面板后，会弹一条非阻断的提示条，告诉你补丁无效。
  补丁在面板里没有条目，不看这条提示就只能靠控制台才发现自己改错了；
* 没有文件、空文件、只有注释、`features: {}` 都是「没有覆盖」，不提示任何错误。

## 维护操作边界

* 「导出配置」「导入配置」「清除本插件配置」只处理目录里的 `feature-*` 配置文件，
  **不包含** `.patch.yml`，这些动作不会改动它。
* 卸载插件时仍按原有行为删除整个插件私有目录，`.patch.yml` 会随目录一起消失；
  需要保留的话请自行备份。
* 面板与面板搜索里不会出现补丁自身的条目、控件、路径、内容或状态。补丁的 `i18n` 段只能覆盖
  已有的文案，不会凭空新增一条没人使用的键。

## 支持的 YAML 写法

只认这份文件真正用得上的写法，其余一律报错（而不是猜）：

* 块状映射，缩进只用空格，每级建议两个空格；
* 值：空值（`key:`、`null`、`~`）、`true` / `false`、纯文本、单引号与双引号字符串、
  行内列表 `[a, b]`、空映射 `{}`、块状列表（每行一项 `- a`）；
* 注释：整行 `# …`，以及值后面隔了空白的 `# …`（引号里的 `#` 不算注释）。

不支持：锚点与别名（`&` / `*`）、多文档（`---`）、块标量（`|` / `>`）、`{}` 之外的行内映射、
标签（`!!`）、Tab 缩进，以及 `yes` / `no` / `on` / `off` 这类有歧义的布尔写法 —— 布尔值请写
`true` / `false`。

> 补丁是高级入口：强行启用一个还没交付的功能、或改动适用端与版本限制之后，插件不承诺它一定能正常工作。
